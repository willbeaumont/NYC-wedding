### Two-color focus treatment closes the v2 accessibility gap

The shared `:focus-visible` treatment now combines a 3px white outline with an 8px deep-green outer ring (`styles.css:54-58`). The white layer distinguishes focus on the deep-green hero, schedule, service note, and footer, while the green layer remains distinct on the paper, travel, white-card, and light-panel backgrounds. This avoids trading the v2 light-surface failure for a new dark-surface failure and applies consistently to navigation, buttons, map links, transit links, copy controls, and the skip link.

The new regression test extracts both focus colors and compares their best contrast against the six light and dark surfaces defined by the page (`tests/site.test.js:138-164`). That directly protects the behavioral requirement that at least one boundary remains visible wherever a control appears, rather than merely asserting that a focus selector exists.

### Static delivery limits trust and preserves the no-JavaScript experience

All itinerary content, addresses, and route links are present in semantic HTML, so failed or disabled JavaScript does not hide essential wedding information. The optional script only updates the countdown, marks the current New York itinerary date, and handles clipboard feedback without injecting HTML.

The page loads no third-party runtime assets. Every external destination uses HTTPS and every new-tab link carries `noopener noreferrer`, limiting opener access when guests leave the static page for Google Maps or the MTA.

### Verification now protects every remediated contract

`env -u NODE_OPTIONS npm run build` validates the three production assets, and `env -u NODE_OPTIONS npm test` passes all 12 tests. The suite covers dates, venues, route copy, current OMNY guidance, semantic landmarks, external-link safety, offline asset constraints, affected 44px touch targets, light-surface text contrast, reduced motion, JavaScript parsing, and focus contrast across all represented surfaces. The recorded rendered checks additionally confirm the computed focus treatment and absence of horizontal overflow; no Dockerfile exists, so container verification does not apply.
