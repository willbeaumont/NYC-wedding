# (v1) Guest-ready Manhattan wedding itinerary

This change delivers a dependency-free, single-page guide that separates Wednesday arrivals from Friday’s 11:00 AM civil ceremony and subsequent Keens meal. It uses semantic HTML and responsive CSS for the core experience, with JavaScript limited to a countdown, current-day emphasis, and copy-address feedback. The venue addresses and subway paths are internally consistent, and live MTA conditions are explicitly deferred to day-of verification. The remaining blockers are a payment instruction that will be obsolete before the event and mobile/accessibility styling that does not meet the stated touch and contrast goals.

Watch for: **confirmed** — guests are told to pick up a MetroCard even though new MetroCard sales end before October 2026; **confirmed** — small gold section labels fall below WCAG AA contrast; **confirmed** — key navigation and map/transit links render with sub-24px target heights on mobile; **confirmed** — the source-presence tests do not catch those rendered accessibility failures.

**Verdict**: NEEDS_CHANGES

## High-level view

The itinerary centers the stable facts—Wednesday, October 7 arrivals; Friday, October 9 vows at 11:00 AM; and an afterward meal without an invented reservation time. Transit guidance is expressed as station-to-station directions with estimated ranges and safe links, while the MTA notice correctly treats service conditions as volatile; the payment checklist is the exception because it recommends an option no longer available by the event.

The responsive layout has no horizontal overflow at either 390px or 1440px, and core content remains present without JavaScript. However, the visual system’s small gold eyebrow text misses contrast requirements on multiple light section backgrounds, and the unpadded inline navigation and route links produce targets only 16.9–19.8px tall on a phone-sized viewport.

The progressive enhancements preserve the underlying itinerary and expose copy feedback through a status region. Build validation and nine Node tests pass, but the accessibility test only searches the stylesheet for selected declarations, so it reports touch readiness without checking which controls receive the minimum size or whether color pairs are readable.

<details><summary>Details</summary>

### MetroCard advice expires before guests arrive

The arrival checklist says “Pick up a MetroCard or set up OMNY contactless payment” (`index.html:77`). This is a **confirmed** guest-facing accuracy problem: MetroCard sales and refills end after December 31, 2025, so an arriving guest cannot pick one up for this October 2026 trip. Remove the MetroCard option and make OMNY/contactless payment the sole acquisition guidance; existing cards do not make “pick up” accurate.

### Small accent text and inline links miss the accessibility goals

The base `.eyebrow` style is 0.73rem text in `#9d6f2f` (`styles.css:61-69`). This is a **confirmed** contrast issue: the pair measures approximately 3.89:1 on `#f5f0e6`, 4.17:1 on `#fbf8f1`, and 3.32:1 on the travel section’s `#e7ded0`, all below the 4.5:1 requirement for text of this size. Darken the base accent color or give these labels a reliably contrasting treatment; the light-on-dark schedule and hero overrides can remain separate.

The phone layout leaves the visible navigation anchors and map/transit `.text-link` anchors as unpadded inline text (`styles.css:103`, `styles.css:230`). This is a **confirmed** touch-target gap: rendered at a 390px viewport, the visible nav links are 16.875px tall and the destination links are about 17–19.8px tall, while only the copy buttons receive the tested 44px minimum. Add block/inline-flex padding or a minimum target size to all primary interactive links without collapsing the spacing between adjacent targets.

### Source-contract tests miss rendered regressions

The nine tests cover critical dates, venue names, route strings, safe external-link attributes, local assets, script parsing, and the presence of responsive and reduced-motion rules. The test named “provides keyboard, mobile, and reduced-motion styling” only regex-matches `:focus-visible`, a media query, and any occurrence of `min-height: 44px` (`tests/site.test.js:77-81`). This is a **confirmed** coverage gap because that last declaration belongs only to `.copy-button`, while the undersized nav and destination links still pass; neither test nor build validation evaluates the base eyebrow color against its actual backgrounds. Add focused checks for the affected selectors/color pairs or document and run a rendered accessibility audit as a release gate, plus a regression assertion that 2026 copy does not invite guests to acquire a MetroCard.
